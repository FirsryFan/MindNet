feat(marks): 记号开放化（不认识的也收）+ 词搭合并 + 文档精简

按用户反馈改三处：

一、记号不再写死（开放集合）
- 认不出来的记号**不再报错**：按"未分类"（role: other）收下，内容不丢，只出一条 unknown-mark 告警。
- 新增 `marks` 声明块：`{"法": {"role": "method", "means": "解题方法/套路"}}`，
  未内置的记号靠声明获得角色；条目级 `role` 优先级最高。
- 角色表：item / passage / method / question / known / note / other（角色名也可自定义）。
  role → 图：item→knowledge、passage→logic、method→**technique**；
  question/known/note/other 不进图但**保留在标准清单里**（附原因）。
- 修饰符同样开放：不认识的保留 + 一条 custom-modifier 告警。
- 缺 `mark`（根本没标）仍然报错 —— 那不是自定义记号，是上游漏填。
- 节点 id 带角色，所以"法"与另一个自定义记号只要角色相同、内容相同 ⇒ 同一个节点。

二、词与搭配不分家
- 「搭/搭配/短语/C」全部并入「词/W」；卡片合并为一张 `EN::Listen::Lex`
  （字段 Text/Meaning/IPA/Audio/Example/Source），不再有 Word/Chunk 两张。
- 节点的 id 前缀统一 `en::w::…`。

三、本步的正产品改成"标准清单"
- 新增 `toStandardItems()`：规范后的条目清单（记号/角色/出处/含义/是否进图/节点 id/取自页边还是点子），
  凡是被标记的东西都会出现在这里（含不进图的提醒与疑问）。
- `convert()` 与 CLI 产出顺序调整为：items.json（标准清单）→ graph_patch.json → run_request.json，
  卡片/TTS/Anki 明确标为"可选的呈现层（不属于本步骤）"。
- CLI `--check` 改为报告"进图 N 节点 / 角色分布 / 不进图清单 / 告警"。

文档精简
- docs/MARKS.md 重写：默认记号 + 两条省事写法 + **§4 记号是开放的**（三种扩展方式、role 去哪）。
- docs/INGEST.md 重写：只讲清单格式、字段规则、AI 不许做的事、转化产物、提示词、命令、概括；
  卡片/模板/TTS/Anki 的细节全部移出（只留一行"可选呈现层"）。

验证：npm test 141/141（新增"记号开放"一条，覆盖未声明/声明/自定义 role/自定义修饰符四种情形）；
`node tools/ingest.js --check` 对示例输出角色分布 item×3 · passage×2 · question×1 · method×1。
